# Бенчмарки

Бенчмарки запускаются через Playwright отдельно от тестов CI. Файлы
`*.pw.bench.ts` — сценарии Playwright, поэтому для их запуска используйте команды
`npm run bench:*`, а не `node` напрямую. Сценарии прогревают сцену перед замером,
повторяют измерения и сохраняют каждый прогон вместе с профилем CPU. Для сравнения
изменений запускайте обе версии кода на одном компьютере, с той же версией Chromium,
режимом питания и частотой экрана. На время замера закройте тяжёлые приложения.
Режимы `headed` и `headless` используют разные сборки Chromium, поэтому их результаты
сравнивать нельзя.

```bash
BENCH_LABEL=before npm run bench:browser

# После перехода на версию кода с изменениями
BENCH_LABEL=after npm run bench:browser

node benchmarks/compare.ts before after
```

Можно запустить каждый сценарий отдельно:

```bash
BENCH_LABEL=rtree-check npm run bench:rtree
BENCH_LABEL=render-check npm run bench:render
BENCH_LABEL=objects-check npm run bench:objects
BENCH_LABEL=offscreen-check npm run bench:offscreen
BENCH_LABEL=collision-check npm run bench:collision-index
BENCH_LABEL=collider-api-check BENCH_MOVING_COUNT=100 npm run bench:collider-api
```

Для воспроизведения нагрузки 4K при замедлении CPU в 20 раз:

```bash
BENCH_LABEL=4k-x20 BENCH_WIDTH=3840 BENCH_HEIGHT=2160 BENCH_CPU_RATE=20 npm run bench:render -- --headed
```

В отчёте сохраняются разрешение, коэффициент замедления CPU и режим запуска браузера.
Если порт 5173 занят, задайте другой через `BENCH_PORT`, например `BENCH_PORT=5174`.

Для измерения только объектов демомира, без дополнительных платформ, задайте `BENCH_SCENE=demo`.
Диагностическая опция `BENCH_EXCLUDE` исключает группы объектов из такого прогона:
`sky`, `fog`, `flow`, `background`. Несколько групп перечисляются через запятую.
Отчёт `render` также показывает медианное время слоёв `background`, `static`, `dynamic`,
`interact`, `main`, `overlay` и `ui`.
`BENCH_RENDER_SCALE` задаёт размер внутреннего буфера относительно окна для
экспериментов с разрешением: например, `0.5` рисует в 1920×1080 при окне 4K.
Этот режим меняет видимую область мира и масштаб изображения; результаты
не следует считать прямым ускорением той же картинки.
`BENCH_RENDERER=webgl` включает экспериментальный WebGL2-фасад основного canvas.
`BENCH_WARMUPS=3` выполняет три прогревочных прохода; для сравнения backend
значение должно быть одинаковым. В WebGL-отчёте также сохраняются загрузки,
вытеснения и оценочный размер кэша текстур. `BENCH_SCREENSHOT=1` сохраняет
снимок кадра.

`compare.ts` — отдельная утилита Node.js; её можно запускать напрямую.

Результаты сохраняются в `benchmarks/results/<label>/` и игнорируются Git. В файлах
`*.json` лежат отдельные замеры, медианы, коммит, версия браузера, модель процессора
и отметка о незакоммиченных изменениях. Файлы `*.cpuprofile` можно открыть в
Chromium DevTools, чтобы найти самые дорогие функции. Сравнение отклоняет результаты,
если различаются сценарий, версия браузера или компьютер.

Бенчмарк `render` запускает демосцену и добавляет 140 платформ. Игрок проходит
маршрут по дороге и верхним ярусам лесов; камера следует за ним. Перед каждым
замером маршрут начинается заново, а перед измерениями выполняется полный прогревочный
проход. Бенчмарк измеряет интервалы между кадрами и время работы событий рендера.
Второй показатель полезен, когда FPS ограничен частотой экрана.

Бенчмарк `rtree` измеряет вставку, поиск первого и лучшего совпадения, а также
удаление. В каждом пакете фиксированы 4 000 прямоугольников и 20 000 запросов;
один замер объединяет четыре пакета, чтобы снизить влияние погрешности таймера.

`objects` сравнивает 100 видимых фоновых объектов с одним запечённым фоном той же
картинки. `BENCH_OBJECT_LAYOUT=baked` выбирает запечённый вариант;
`BENCH_RENDERER=webgl` включает WebGL2 для обоих вариантов.

`offscreen` сравнивает движущиеся объекты за пределами экрана. Режим задаётся через
`BENCH_OFFSCREEN_MODE=active|paused|shadowed|culled|absent`, количество — через
`BENCH_OFFSCREEN_COUNT`. `culled` — экспериментальный подкласс только в бенчмарке:
он пропускает запись далёких объектов в динамическое дерево, сохраняя их движение.

`collision-index` сравнивает полную перестройку дерева из 500 объектов с двумя
деревьями, где неподвижные объекты сохраняются между кадрами. `BENCH_MOVING_COUNT`
задаёт число движущихся объектов (`0`, `100` или `500`), а
`BENCH_SWAPS_PER_FRAME` — число обменов между деревьями за кадр.

```bash
BENCH_LABEL=split-100 BENCH_MOVING_COUNT=100 BENCH_SWAPS_PER_FRAME=10 BENCH_CPU_RATE=20 npm run bench:collision-index -- --headed
```

Бенчмарки не используют порог «прошёл/не прошёл». Команда сравнения отмечает
пересечение диапазонов повторных замеров: небольшую разницу в таком случае нельзя
уверенно приписать изменению кода.

`collider-api` измеряет текущий API `ColliderObject` на 500 коллайдерах за 24 кадра.
`BENCH_MOVING_COUNT` задаёт число движущихся коллайдеров от 0 до 500. Вариант
с переключением хранит стоящие коллайдеры в статическом дереве; базовый вариант
каждый кадр заново записывает все 500 в динамическое. Отдельно измеряются
обновление деревьев и 160 запросов `findBestCollision` за кадр. Базовый вариант
тоже вызывает поиск в обоих деревьях, хотя статическое дерево у него пусто.
Он воссоздан в сценарии бенчмарка, поэтому это сравнение алгоритмов на текущем коде,
а не запуск старой версии проекта. Отрисовка и полная физика игрока не измеряются.
