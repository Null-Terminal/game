# Бенчмарки

Бенчмарки запускаются через Playwright отдельно от тестов CI. Файлы `*.pw.bench.ts` — сценарии браузера; запускайте их командами `npm run bench:*`.

Каждый сценарий прогревает сцену, повторяет замеры и сохраняет отдельные прогоны вместе с профилем CPU.

## Запуск и сравнение

Сначала измерьте исходную версию, затем версию с изменениями:

```bash
BENCH_LABEL=before npm run bench:browser

# После перехода на версию кода с изменениями
BENCH_LABEL=after npm run bench:browser

node benchmarks/compare.ts before after
```

`compare.ts` — отдельная утилита Node.js. Её можно запускать напрямую.

Чтобы сравнение было корректным, запускайте обе версии на одном компьютере и с одной версией Chromium. Сохраняйте одинаковые режим питания и частоту экрана. На время замера закройте тяжёлые приложения.

Режимы `headed` и `headless` используют разные сборки Chromium. Их результаты сравнивать нельзя.

Бенчмарки не используют порог «прошёл/не прошёл». Команда сравнения отмечает пересечение диапазонов повторных замеров: небольшую разницу в таком случае нельзя уверенно приписать изменению кода.

### Отдельные сценарии

```bash
BENCH_LABEL=rtree-check npm run bench:rtree
BENCH_LABEL=render-check npm run bench:render
BENCH_LABEL=objects-check npm run bench:objects
BENCH_LABEL=offscreen-check npm run bench:offscreen
BENCH_LABEL=collision-check npm run bench:collision-index
BENCH_LABEL=collider-api-check BENCH_MOVING_COUNT=100 npm run bench:collider-api
```

Если порт 5173 занят, задайте другой через `BENCH_PORT`, например `BENCH_PORT=5174`.

## Сценарии

### Рендеринг (`render`)

Сценарий запускает демосцену и добавляет 140 платформ. Игрок проходит маршрут по дороге и верхним ярусам лесов, а камера следует за ним.

Перед измерениями выполняется полный прогревочный проход. Перед каждым замером маршрут начинается заново.

Сценарий измеряет интервалы между кадрами и время работы событий рендера. Второй показатель полезен, когда FPS ограничен частотой экрана. В отчёте есть медианное время слоёв `background`, `scene`, `interact`, `main`, `overlay` и `ui`.

Параметры:

- `BENCH_SCENE=demo` измеряет только объекты демомира, без дополнительных платформ.
- `BENCH_EXCLUDE` исключает группы объектов из такого прогона: `sky`, `fog`, `flow`, `background`. Несколько групп перечисляются через запятую.
- `BENCH_RENDER_SCALE` задаёт размер внутреннего буфера относительно окна. Например, `0.5` рисует в 1920×1080 при окне 4K. Это меняет видимую область мира и масштаб изображения, поэтому результат нельзя считать прямым ускорением той же картинки.
- `BENCH_RENDERER=webgl` включает экспериментальный WebGL2-фасад основного canvas.
- `BENCH_WARMUPS=3` выполняет три прогревочных прохода. Для сравнения вариантов значение должно совпадать.
- `BENCH_SCREENSHOT=1` сохраняет снимок кадра.

Пример нагрузки 4K с замедлением CPU в 20 раз:

```bash
BENCH_LABEL=4k-x20 BENCH_WIDTH=3840 BENCH_HEIGHT=2160 BENCH_CPU_RATE=20 npm run bench:render -- --headed
```

### Пространственный индекс (`rtree`)

Сценарий измеряет вставку, поиск первого и лучшего совпадения, а также удаление.

В каждом пакете фиксированы 4 000 прямоугольников и 20 000 запросов. Один замер объединяет четыре пакета, чтобы снизить влияние погрешности таймера.

### Число объектов (`objects`)

Сценарий сравнивает 100 видимых фоновых объектов с одним запечённым фоном той же картинки.

`BENCH_OBJECT_LAYOUT=baked` выбирает запечённый вариант. `BENCH_RENDERER=webgl` включает WebGL2 для обоих вариантов.

### Объекты вне экрана (`offscreen`)

Сценарий сравнивает движущиеся объекты за пределами экрана.

- `BENCH_OFFSCREEN_MODE=active|paused|sleep|culled|absent` выбирает режим.
- `BENCH_OFFSCREEN_COUNT` задаёт число объектов.
- `BENCH_OBJECT_KIND=collider` запускает сценарий с `ColliderObject`. По умолчанию используются обычные объекты.
- `BENCH_OFFSCREEN_LAYOUT=spread` распределяет объекты по двадцати экранам и ведёт камеру через десять экранов за замер.

Режим `sleep` использует штатное усыпление игры относительно камеры. `culled` доступен только для обычных объектов: экспериментальный подкласс пропускает запись далёких объектов в динамическое дерево, сохраняя их движение.

В отчёте сохраняется число бодрствующих объектов в конце маршрута.

### Деревья коллизий (`collision-index`)

Сценарий сравнивает полную перестройку дерева из 500 объектов с двумя деревьями, где неподвижные объекты сохраняются между кадрами.

`BENCH_MOVING_COUNT` задаёт число движущихся объектов: `0`, `100` или `500`. `BENCH_SWAPS_PER_FRAME` задаёт число обменов между деревьями за кадр.

```bash
BENCH_LABEL=split-100 BENCH_MOVING_COUNT=100 BENCH_SWAPS_PER_FRAME=10 BENCH_CPU_RATE=20 npm run bench:collision-index -- --headed
```

### API коллайдеров (`collider-api`)

Сценарий измеряет текущий API `ColliderObject` на 500 коллайдерах за 24 кадра. `BENCH_MOVING_COUNT` задаёт число движущихся коллайдеров от 0 до 500.

Вариант с переключением хранит стоящие коллайдеры в статическом дереве. Базовый вариант каждый кадр заново записывает все 500 объектов в динамическое дерево. Отдельно измеряются обновление деревьев и 160 запросов `findBestCollision` за кадр.

Базовый вариант тоже вызывает поиск в обоих деревьях, хотя статическое дерево у него пусто. Он воссоздан в сценарии бенчмарка, поэтому это сравнение алгоритмов на текущем коде, а не запуск старой версии проекта.

Отрисовка и полная физика игрока не измеряются.

## Отчёты

Результаты сохраняются в `benchmarks/results/<label>/` и игнорируются Git. Файлы `*.json` содержат отдельные замеры, медианы, коммит, версию браузера, модель процессора и отметку о незакоммиченных изменениях.

Файлы `*.cpuprofile` можно открыть в Chromium DevTools, чтобы найти самые дорогие функции. Сравнение отклоняет результаты, если различаются сценарий, версия браузера или компьютер.

В WebGL-отчёте также сохраняются загрузки, вытеснения и оценочный размер кэша текстур.
